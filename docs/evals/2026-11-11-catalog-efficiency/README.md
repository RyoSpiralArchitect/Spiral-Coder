# Catalog request and time efficiency

The unit remains Coder + Observer, both `gpt-5.6-luna`. The task is the original
replay catalog from [issue #49](https://github.com/RyoSpiralArchitect/Spiral-Coder/issues/49).
Completion, independent qualification and efficiency are separate measurements.

## Runtime changes

Authored acceptance rows can now cite `@required-4` instead of retyping a long
shell command. The ID selects an existing, current successful native receipt
from the current task's check catalog. Failed reruns, later edits, unknown IDs
and a new task cannot supply that receipt. Both role schemas offer the same
short choices. The runtime preserves provider arguments and criterion decisions;
it resolves the command only inside the existing validation path. Full original
commands remain valid. Report text still has to meet its own requirements.

When required artifact edits and the baseline reproduction are recorded, the
next-action prompt prefers a pending formatting check before expensive final
checks. Diagnosis and a required recheck take precedence. The preference is
advice; it adds no gate and discharges no check. All final checks still need
their own successful native results after the last mutation.

The [full local checks](runtime-checks.json) passed, including 1,133 main Rust
tests and 20/20 TUI replays. A vocabulary assertion in an earlier all-target run
was updated to check both the short enum and the retained original command.

## Guide diagnostics for the next run

The old public guide check used the same bare `AssertionError` for an absent
guide example and a mismatch. In R23, the pair ran it before the guide edit and
returned to catalog edits after seeing valid candidate JSON followed by that
error. The [next input materializer](diagnostic_inputs.py) names the missing or
duplicate marker, distinguishes a mismatch, and retains the exact comparison
and count predicates. Only that one command in the prompt changes.

The [model-free control](guide-diagnostic-control.json) checked the same actual
native output against missing, incorrect, matching and duplicate examples.
The two commands returned identical exit statuses and stdout. This is a
prospective diagnostic improvement; no fresh provider run used it yet. The
next efficiency target is completing all required artifacts before the final
check cycle and avoiding repeated builds of partially connected edits.
