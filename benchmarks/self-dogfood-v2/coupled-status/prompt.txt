- Validate positive max_iterations and max_task_requests_per_iteration, their checked product equals max_task_requests, max_wire_requests >= max_task_requests, row count <= max_iterations, row order 1..N and exact directories iteration-01, iteration-02, etc. Require unique nonempty task IDs and exact parent_task_id linkage starting with null. Each row's task ID and counts must match its ledger and task count must not exceed max_task_requests_per_iteration. Row completed must equal termination==completed; only the last row can be completed, and only in a completed manifest. A completed manifest requires a completed last row, stop_reason=completed, and no active or interrupted iteration. Manifest completed must equal stop_reason==completed.
- A pending iteration may be named by active_iteration or interrupted_iteration.directory, never both. Its directory must be iteration-N+1 within max_iterations; a pending task ID must be new. Active requires null stop_reason; interrupted requires stop_reason=interrupted. Its ledger is read at the same relative path. Missing pending ledger is valid and means unknown usage, represented by null, never zero. An existing malformed pending ledger is an error. In-flight count is the number of requests with status=in_flight_or_interrupted.
- For a normal or active run, manifest task_requests/wire_requests must equal finalized row sums (native manifests omit ongoing spend). For an interrupted run, both interrupted_iteration counts must match the pending ledger, or both null if absent; manifest totals must equal finalized+pending counts, or null if absent. Include pending spend exactly once in output. Reject overflow and known aggregate usage above the declared caps.
- Reject malformed JSON, unsupported versions, missing finalized ledgers, mismatched counts/links, traversal directories, and any symlink below the run directory on a manifest/ledger path. Return nonzero with nonempty stderr and empty stdout. A caller-supplied run directory itself may resolve normally. For success, stdout must contain exactly one JSON object with the exact fields shown by scripts.status_fixture.expected; array order and progress string order are preserved. No extra fields. status is completed for a completed record, stopped when a stop_reason exists, otherwise running. This is recorded native status, never independent qualification or promotion authorization.
- Include finalized rows with iteration, task_id, termination, task_requests, wire_requests, changed_files and newly_verified. Include pending as null or {directory, task_id, task_requests, wire_requests, in_flight_requests}, with unknown fields null. requests has task_used, wire_used, task_limit, wire_limit, task_remaining, wire_remaining; if pending usage is unknown, both used and remaining totals are null. Limits remain known. Empty-start manifests are valid if their totals are zero.
